# Model evaluation

Full report: [`reports/model_evaluation_report.md`](../reports/model_evaluation_report.md) (generated by `python scripts/evaluate.py`).
Full Kaggle dataset (284,807 transactions), chronological 60/20/20 split; thresholds tuned on validation for an 80 % recall target;
results below are on the held-out test split (56,746 transactions the model never saw).

## Headline results

| | Logistic regression baseline | **XGBoost (serving)** | Improvement |
|---|---|---|---|
| False positives | 91 | **49** | **-46 %** |
| Transactions sent to manual review | 153 | **106** | **-31 %** |
| Legitimate customer spend wrongly flagged | EUR 66,282 | **EUR 35,420** | **-47 %** |
| Precision | 0.405 | **0.538** | **+33 %** |
| PR-AUC | 0.744 | **0.776** | **+0.032** |
| Total fraud cost (missed fraud + EUR 5 per review) | EUR 3,135 | **EUR 2,931** | **-7 %** |

* Catches **69 % of fraud value** (EUR 5,327 of EUR 7,728) and cuts total fraud cost by **62 % vs. no screening**.
* **p99 latency 9.8 ms** per prediction over HTTP, 260 requests/s on a laptop ([benchmarks](benchmarks.md)).
* Serving model chosen automatically: XGBoost and XGBoost + Isolation Forest blends are compared on validation PR-AUC, and the best one is deployed.
