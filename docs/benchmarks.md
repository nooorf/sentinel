# Latency benchmark

Generated by `python scripts/benchmark.py --spawn` (raw output: `reports/benchmark.{json,md}`).
Model `v20261012074136-adf95d2a` (XGBoost decision path), 1 uvicorn worker, MacBook Pro (Apple Silicon, 8 CPU, 8 GB RAM),
macOS 14.4.1, Python 3.11.16. Client and server share the machine (Python thread-pool client), so HTTP numbers include client overhead.

| Scenario | p50 (ms) | p95 (ms) | p99 (ms) | n |
|---|---|---|---|---|
| Model only, 1 row (preprocessing + all models) | 1.90 | 2.04 | 2.13 | 300 |
| Model only, batch of 100 | 2.68 | 2.79 | 2.85 | 30 |
| HTTP `POST /predict`, sequential | 3.81 | 4.23 | 9.75 | 300 |
| HTTP `POST /predict/batch`, 100 rows | 10.87 | 11.03 | 11.08 | 30 |
| HTTP `POST /predict`, 8 concurrent clients | 29.73 | 40.42 | 60.75 | 600 |

Throughput at concurrency 8: **260 req/s**. The sub-100 ms target holds at p99 in every scenario.
HTTP latency includes request validation and the synchronous SQLite write of each event for drift monitoring.

MLflow experiment `sentinel` (SQLite DB at `var/mlflow.db`): `mlflow ui --backend-store-uri sqlite:///var/mlflow.db`.
